## P3 DAG 拓扑校验（启动期环检测，fail-fast）
- **目标**：避免“依赖缺失/环 → 静默产出错误数据”。
- **关键发现（架构约束）**：系统采用「模块图 + cli 直接注入」混合模型，`raw.*`/`features.*`/`marketData.*` 三命名空间均有大量键由 cli 层（数据/特征/postprocess）直接写入 `ctx`，无对应模块 provider。静态无法区分「cli 注入」与「真缺失」——盲目对缺失依赖硬失败会误伤现有正常 pipeline。
- **收敛方案**：校验器只做**可靠的循环依赖检测**（Kahn 拓扑排序，零误报），这是静态可判定且会导致静默错误数据的最危险结构问题。缺失依赖的完整检测需引入「外部输入清单 manifest」，属更大重构，按用户「改造节制」偏好暂不纳入。
- **改动**：`daily_review/pipeline/runner.py` 新增 `validate_pipeline_dag(modules)`（种子域判定 `_is_seed_require` + 模块间依赖边 + 环检测，自依赖排除），`Runner.run()` 于模块执行前调用它（fail-fast），并暴露 `Runner.validate()` 供显式校验；移除遗留的无用 `strict` 参数。
- **验证**：编写 6 例测试（正向 ALL_MODULES=44/V3_MODULES=12 无环通过；反向 2/3 节点环被捕获、自依赖/合法边/cli 注入键不误报），全部通过；runner.py + cli.py 均 py_compile 通过。
- **后续建议**：若要补「缺失依赖」检测，最小方案是新增 `EXTERNAL_INPUTS` 清单（cli 注入的 marketData 键集合）传给校验器做差集；或重构为显式“外部输入声明”。

## 核心算法剖析（metrics/ 42 文件，亲验 High 级项）
- **方法**：先由 Explore 代理全量扫描 + 主题分组，再亲读 `v3_position.py`/`v3_rightside.py`/`v3_sentiment.py` 及调用方 `modules_v2/sentiment/v3_sentiment.py` 核实，修正代理两处口径。
- **最大结构性问题：v2/v3 同义算法在 metrics/ 内部大量重复且互相矛盾**（非 modules_v2 重写——后者是薄封装 `from metrics.X import`）。并存对：情绪评分(spec/v2/v3 三套阈值全不同)、`_score_zt_heat`/`_score_collapse_chain`/`infer_phase`(各两版逻辑分歧)、龙头三要素(dragon_v2/god_form/dujie 三版字段契约不同)、仓位五档(position_v2/v3/fullposition/resonance 四套范式)、右侧确认(rightside_v2 3信号 vs v3 5信号)、反弹三阶段(rebound_v2/v3 双版)。pipeline 同时挂 v2/v3 会输出互相矛盾结论。
- **High①（亲验）`v3_position.py` 档位错配**：docstring 按 win_rate 档位（60%以下空仓），但 `TIER_CONFIG` 阈值(0.9/0.8/0.7/0.6)作用在 `edge=凯利缩放值` 上。典型 odds=1.5~2.5 时 edge 落 0.6~1.2 → 50~60% 胜率被判定正常/重仓区，与养家心法"60%以下空仓"错位。安全阀(108行)仅把"未满仓共振且>=0.9"兜到 0.7，中段仍系统性偏高。另有 101 行 `state_state` 未定义变量（被 `dir()` 短路保命）属死代码，103-104 才用正确 `_sp`。
- **High②（亲验修正）`v3_rightside.py` fail-open**：代理称"全空输入→allowed=True"不成立（实测空输入 score=3、allowed=False）。真实缺陷是**缺数据默认信号 True**（85/92/98/132 行：index/sector/stock 数据 None 或 ma5 缺失时信号默认通过），部分数据即"制造"通过信号——交易闸门应为 fail-closed。且 `confidence=66+score*6-...` 对空数据 wait 仍可给 84，置信度名不副实。
- **非 bug 澄清**：`v3_sentiment.calc_sentiment_score(d)` 用 `d.zt_count` 属性访问，调用方 `modules_v2/sentiment/v3_sentiment.py` 经 `v3_validator.validate_and_clean` 把 dict 包成属性对象，接口自洽，非崩溃点。
- **其余 Med/Low（代理核实）**：`v3_god_form`/`v3_mainstream` 需 change_pct/ma5/market_share 等当前 ztgc 缓存不提供的字段 → 常年跑默认值退化(NO_THEME/非龙头)；`leader.is_one_word_limitup` 启发式 `hs_p10=1.2` 写死；`mood.py` 默认 `aggressive` 偏多；`zt_analysis.py` 大量无注释魔法系数(742-746区 jj_rate*1.55 等)；约 20 处 `_to_num/_clamp` 私有副本（应统一到 `daily_review/utils/num.py`，已存在 `to_float/to_int`）。
- **结论**：无会令整条 pipeline 崩塌的除零/越界硬 bug（try/except+默认值兜底充分）；但 1 个资金风险(High①仓位超配)、1 个虚假信号风险(High② fail-open) + v2/v3 重复矛盾，是优先级最高的三处重构。
